REST services usage

  • URL REST service
  • Authentication process
  • Services calling

REST Service data obtaining is performed by calling an URL with some parameters, using POST method.

URL REST service

https://www6.siketing.com/observer/rest/

In the call to a service, it is necessary to specify two parameters, the service being called, and the parameters passed to it.

Parameter

Value

method

Called service name

params

Service parameters (JSON Objects)

In order to access the REST Services you need to send a token as a parameter. The token is generated by the server and returned to client on successful authentication. A token lifespan is 24hrs. If a timed out token is used, server will respond with RNE002 error (see Annex I. Error list)

Authentication process

Service authentication is performed by calling authRest service with login and passwod parameters.

Parameter

Value

method

authRest

params

Authentication call parameters:

  • login: User name

  • password: User password

Services calling

Once authenticated in the REST server, calls can be made to the services.

  • All calls must be made over HTTPS and using the POST method.

  • The parameters must be in the body of the request. Never in the URL.

  • The params parameter must always include the key and the authType

Request example:

curl --location 'https://www6.siketing.com/observer/rest/' \
--form 'method="getAppZonesPublic"' \
--form 'params="{\"key\":\"f2e0cf0eb57fc6e25ff40fe7af080efc\",\"app_id\":\"20132013225\",\"zone_type\":\"0,11,12,13,14\"}"'

getAppZonesPublic

Method

getAppZonesPublic

Status

Production / Public

Description

Permit to obtain information about zones that are configured in a App/Location

Parameters

  • app_id: App/Location Identifier.

  • zone_type: Types of zone to visualize (comma-separated):

    • "0": Simple zone. Single node zone.

    • “1”: Zone Sum. Sum of several zones (Unique visitors are not added).

    • "3": Nodes Union. Multi-node zone.

    • "6": Flows between zones. Devices that visit one zone and then another zone.

    • “9”: Path between Zones. Devices that visit one zone and then another zone (allows an intermediate pass-through zone).

    • “10”: Zone Sum Opp + Sum UV. Sum of several zones (adding unique visitors).

    • “11”: Path By Stages: Zone representing a stage of a road (does not include the starting stage).

    • "12”: Sum Paths By Stages: Sum of Path By Stages.

    • “13”: Path By Stages Header: Zone representing a starting stage of a road.

    • “14”: Prediction: Zone with predictive data.

Type

POST

Answer
(Control)

  • isError : Boolean ( true / false)

  • errorType:  Type of Error

  • errorDesc: Description of Error

  • errorNum: Number of Error

  • response: content of response

Answer
(response)

  • status: result of the query

  • records: quantity of the numbers returned

  • data: Information about configured zones in the installation

Answer
(data)

Every element of the array is composed by the fields:

  • id: Zone Identifier

  • app_id: App identifier

  • name: Name of the Zone

  • short_name: Short name of the zone

  • description: Description of the zone

  • initial_time: Time of creation of the zone

  • final_time: Time up to be active the zone

  • movement_timeout_s: Time of displacement between zones

  • display_order: Position that the zone has in the lists of the installation

  • status: Status of the zone. Determines if the zone is visible on the dashboard..

  • all_center: It says if the zone represents the complete installation (1)

  • operation_id: Type of operation of the zone:

  • nodes: Nodes that belongs to the zone

  • nodes_ids: Identifiers of the nodes that belongs to the zonesee

  • active: It says if the zone is active (1) or inactive (0). If it is active, it will be included in the calculation of visits.

getZoneVisitsH

Status

Production / Public

Description

It returns all the information related to the visits of a zone in a period of time.

  • end (Required): End time of the period to visualize (seconds UTC since 01-01-1970).

  • type (Required): Type of group of visits / opportunities:

    • "hh": By hours.

    • "dd": By days.

    • "ww": By weeks.

    • "mm": By months.

  • profile : Profile Identifier. Default: 0 (All Profiles)

Tipo

POST

Answer
(Control)

  • errorType:  Type of Error

  • errorDesc: Description of Error

  • errorNum: Number of Error

  • response: content of response

Answer
(response)

  • status: Result of the query

  • records: quantity of the numbers returned

  • data: Detected devices grouped by hours, days...


(data)

Each array element is composed by:

  • timestamp: Timestamp (Local Timezone).

  • zone_id: Zone Identifier

  • visits: Total visits (news + recurrents)

  • new_visits: New visitors (Detected never before)

  • recurrents: Recurrent visitors in zone.

  • recurrents_dist: Recurrent visitors in distribution.

  • recurrents_today: Recurrent visitors in zone today.

  • data: Data of requested paths prepared to show in a Sankey Diagram

    • raw_data: Dataset

      • Origin Zone Name

      • Origin Zone Total Data

      • Origin Zone Percentage Data

      • Destination Zone Percentage Data

      • Destination Zone Total Data

      • Destination Zone Name

    • colors_left: Colors that will be used to draw the graph.

    • colors_right: Colors that will be used to draw the graph.

    • first_col: Zone names of the first column.

    • second_col: Names of zones of the second column.

    • third_col: Names of zones of the second column (Only if Paths of 3 zones are configured)
